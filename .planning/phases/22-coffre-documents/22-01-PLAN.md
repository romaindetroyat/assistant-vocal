# Plan 22-01 — Coffre de documents chiffré (perso et pro)

## Objectif
Ajouter un document (photo ou PDF : permis, carte grise, RIB, contrat, dossier client) par le trombone, la caméra ou
le partage iPhone ; l'assistant en extrait une fiche structurée, à valider ; le fichier est chiffré avant stockage ;
ensuite « quel est le numéro de ma carte grise ? », « le dossier de Mme Durand ? », « quels documents expirent
bientôt ? » répondent depuis les fiches. Deux espaces : perso et pro. Page « Mes documents ».

## Décisions
- **Chiffrement côté serveur** : AES-256-GCM (WebCrypto), clé = secret `DOCS_KEY` (32 octets hex) si présent, sinon
  dérivée de `SESSION_SECRET` par HKDF-SHA256 (info « coffre-documents ») ; IV aléatoire par fichier ; la clé ne
  quitte jamais le serveur. Fiches (métadonnées, champs extraits) stockées en clair dans le KV comme le reste
  (même niveau de protection que la mémoire et les tâches) ; les champs marqués sensibles (numéros d'identité,
  IBAN, mots de passe) sont **chiffrés eux aussi** et ne sont déchiffrés qu'à la lecture confirmée.
- **Stockage binaire** : façade `server/blobs.js` : R2 si le binding `DOCS` existe (bucket à créer plus tard, R2 pas
  encore activé sur le compte), sinon KV (`blob:<id>`, valeurs binaires jusqu'à 25 Mo) ; Node : fichiers dans
  `DATA_DIR/blobs/`. Limite d'envoi 20 Mo ; types : JPEG, PNG, WebP, PDF (HEIC refusé avec message).
- **Extraction** : un appel Claude (`client.beta.messages.create`, modèle `config.model`, effort `low`, pas d'outil,
  blocs `image` ou `document` base64 ; PDF > 100 pages refusé) demandant un JSON strict : `{ titre, type
  (identite|vehicule|banque|assurance|sante|logement|contrat|facture|client|autre), espace (perso|pro),
  personne (titulaire ou client), organisme, dateDocument, dateExpiration, champs: [{nom, valeur, sensible}],
  resume (3 phrases), motsCles: [] }`. Validation stricte ; l'utilisateur **valide ou corrige** la fiche dans la page
  avant qu'elle ne soit interrogeable (état `aValider` tant que non validée ; l'assistant peut la lire mais le dit).
- **Outils locaux** (non stricts) : `document_chercher({ requete, espace })` → liste titre/type/personne/date/id +
  résumé, recherche par mots-clés sur titre, personne, organisme, motsCles, résumé et noms de champs ;
  `document_lire({ id, confirme })` → fiche complète ; si la fiche contient des champs sensibles et `confirme` est
  faux, renvoie la fiche sans ces champs et demande une confirmation orale explicite (« dis “oui, lis-le” ») ;
  `document_expirations({ jours })` → documents expirant dans N jours. Prompt : règles d'usage et de discrétion
  (jamais lire un champ sensible sans confirmation ; en mode voiture, jamais).
- **Entrées** : `POST /api/documents` (multipart `fichier` + `espace` facultatif ; cookie ou jeton d'appareil) ;
  bouton « Ajouter au coffre » sur une image jointe dans l'app ; partage iPhone / extension : consigne contenant
  « coffre », « classe », « range » → `traiterPartage` route le fichier vers le coffre au lieu de la conversation.
- **Page `/documents`** : liste filtrable (perso/pro, type, recherche), fiche dépliable avec champs (sensibles
  masqués, bouton « Afficher »), validation/correction des champs, téléchargement de l'original déchiffré
  (`GET /api/documents/:id/fichier`, cookie seulement), suppression. Lien dans le tiroir et dans Mes outils.
- **Brief** : phrase « documents à renouveler » si une expiration tombe dans les 60 jours.

## Tâches
1. `server/blobs.js` (façade R2/KV/fs) + `server/chiffrement.js` (clé, chiffrer/déchiffrer ArrayBuffer et chaînes) +
   tests (aller-retour, IV différents, clé dérivée stable).
2. `server/documents.js` : ajout (validation type/taille, chiffrement, blob, extraction, fiche), liste, recherche,
   lecture, validation, suppression, expirations ; outils ; branchement `tools.js`, `prompt.js`, `brief.js`,
   `partage.js` ; routes `app.js` (`/api/documents*`, page `/documents`) ; `worker.js` passe `env.DOCS` s'il existe
   (binding optionnel dans `wrangler.jsonc` en commentaire, à activer quand le bucket existe).
3. Front : `public/documents.html` (+ ajout dans `sw.js` SHELL et `CACHE` +1), bouton « Ajouter au coffre » dans
   `app.js`, liens tiroir et Mes outils.
4. Tests `test/documents.test.js` (client simulé renvoyant un JSON de fiche ; fichier chiffré illisible dans le blob ;
   champs sensibles masqués sans confirmation ; recherche ; expirations ; routes 401/413/415 ; partage « range »).
5. SUMMARY ; STATE/ROADMAP par l'orchestrateur.

## Vérifications
`npm test` vert ; en production : envoi d'une image de test → fiche extraite, `document_chercher` la retrouve,
original téléchargeable ; champ sensible refusé sans confirmation.
