# Plan 21-01 — Extension Chromium, raccourcis clavier, autorisations fluides

## Objectif
Depuis Chrome/Chromium/Edge/Brave : un raccourci global ouvre l'assistant et lance l'écoute ; clic droit « Envoyer à
l'assistant » sur une sélection, un lien ou la page ; dans l'app, raccourcis clavier ; micro et position accordés une
fois et conservés ; page « Vérifier mes autorisations » dans Mes outils.

## Décisions
- **Extension Manifest V3 non empaquetée** (dossier `extension/` du dépôt, chargée via chrome://extensions → mode
  développeur ; zip fourni par `npm run extension:zip`). Pas de Web Store.
- **L'app reste first-party** : l'extension n'encapsule pas l'assistant dans un iframe (cookies tiers bloqués, micro
  non persistant) ; elle ouvre une **fenêtre dédiée** de l'app (`chrome.windows.create`, type popup, 440×820) et la
  réutilise (focus) à chaque appel. Le raccourci global passe `?action=appel`.
- **Authentification de l'extension** : jeton d'appareil (phase 17) saisi une fois dans la page d'options ; appels
  `POST /api/partage` et `POST /api/raccourci` avec `Authorization: Bearer`. Le serveur ajoute **CORS** pour les
  origines `chrome-extension://` sur ces deux routes (préflight OPTIONS avec Authorization).
- **Raccourcis** : extension `commands` (Ctrl+Maj+Espace : ouvrir + parler ; Ctrl+Maj+E : envoyer la page) ;
  app : Espace maintenue = parler (hors champ de saisie), Ctrl+Espace = appel on/off, Échap = raccrocher / quitter la
  veille, Ctrl+K = saisie.
- **Autorisations** : micro demandé une fois et flux conservé tant que l'app est visible (fermé quand l'onglet est
  caché > 2 min) ; position demandée au plus une fois par heure ; section « Autorisations » dans Mes outils avec
  `navigator.permissions.query` (micro, position, notifications) et, pour chaque état « prompt/denied », la marche à
  suivre Chrome et iPhone.

## Tâches
A. **Extension** (`extension/`) : `manifest.json` (MV3, `sidePanel` non utilisé, `commands`, `contextMenus`,
   `storage`, `windows`, `tabs`, `scripting`, `host_permissions` sur l'hôte de l'assistant), `background.js`
   (service worker : commandes, menus « Envoyer la sélection / le lien / la page à l'assistant », fenêtre dédiée
   réutilisée, extraction du texte de la page par `chrome.scripting.executeScript` limitée à 20 000 caractères,
   envoi à `/api/partage` avec consigne saisie via `prompt` dans la page ou vide, notification du résultat),
   `options.html/js` (hôte, jeton, test), icônes SVG/PNG, `README.md` d'installation. `scripts/extension-zip.mjs`.
   Serveur : CORS sur `/api/partage` et `/api/raccourci` (`Access-Control-Allow-Origin` = origine `chrome-extension://…`
   reçue, `Allow-Headers: Authorization, Content-Type`, OPTIONS 204) + test.
   Guide dans « Mes outils › Appareils et raccourcis » (sous-section Extension Chromium : installation, jeton, raccourcis).
B. **App** (`public/app.js`, `outils.html`, `styles.css`) : raccourcis clavier ; micro conservé (réutilise `veille.flux`
   / `appel.recupererFlux()` : un seul flux pour dictée, vocal, appel, veille ; fermé après 2 min caché) ; position
   mise en cache 60 min ; section « Autorisations » (états, boutons « Demander maintenant », marche à suivre) ;
   `CACHE` du service worker +1.
C. Tests (`test/extension.test.js` : CORS préflight et réponse, manifeste valide, zip) ; SUMMARY ; STATE/ROADMAP par
   l'orchestrateur.

## Vérifications
`npm test` vert ; `node --check` du front et de l'extension ; en production : préflight OPTIONS depuis une origine
chrome-extension renvoie 204 avec les bons en-têtes ; test réel par Romain : charger l'extension, Ctrl+Maj+Espace.
