# Phase 24 — Modèle automatique

## Objectif
L'assistant choisit seul le modèle à chaque demande : Haiku 5.5 pour les questions simples (≈ 2 s, ≈ 0,05 ct),
Opus 5.5 pour les vraies tâches, sans toucher au curseur. Plus rapide et moins cher au quotidien.

## Exigences
- AUTO-01 Réglage `modele: 'auto'` (nouveau défaut) ; Haiku, Sonnet, Opus restent forçables.
- AUTO-02 Routage par règles, instantané : pièce jointe, message long, rédaction, analyse, conseil, envoi de mail → Opus ;
  le reste (heure, météo, agenda, rappels, courses, tâches, trajets, adresses) → Haiku. Uniquement pour chat, voix, Siri, partage
  (brief, documents, consolidation gardent le modèle par défaut).
- AUTO-03 Garde-fou : en mode auto, Haiku dispose d'un outil `escalader` ; s'il juge la demande trop difficile, le tour repart
  aussitôt sur Opus (le message de Haiku n'est pas conservé).
- AUTO-04 Visibilité : événement `modele` (SSE) affiché discrètement dans la transcription ; `/api/voice/ask` renvoie `modele`.
- AUTO-05 Consommation : tokens et coût par modèle (tarifs Haiku 0,10/0,50, Sonnet 2/10, Opus 4/20 $ par million ; cache
  lecture 0,1 ×, écriture 1 h 2 ×), coût total juste dans « Mes outils ».
- AUTO-06 Interface : bouton « Auto » dans le dock (curseur grisé quand il est actif), option dans Réglages.

## Tâches
1. `server/routage.js` (règles + définition de l'outil `escalader`), `reglages.js` (entrée `auto`, défaut), `chat.js` (choix,
   escalade, événement `modele`, recherche web adaptée au modèle), `usage.js` (par modèle), `app.js` (voice/ask), `prompt.js`.
2. Front : dock (bouton Auto), badge du modèle, `outils.html` (consommation par modèle). Cache SW.
3. Tests : règles, requête Haiku vs Opus, escalade, coût par modèle.

## Vérification
`npm test` vert ; rendu sans erreur ; en production, lecture seule de `/api/usage` après usage réel par Romain.
